## 一、名称归一

### N1. 短缩写不得单独作为病名证据【严重，系统性，最先修】
- **现象**：LRPPRC 病名清单 `Leigh syndrome / LS / LSS`，10 条新试验 9 条靠缩写进来：小细胞肺癌 "LS-SCLC"（5）、HIV 抗体 "3BNC117-LS" 等（3）、"Lumbar Spinal Stenosis (LSS)"（1）。
- **规则（2026-11-11 定）**：**大写短缩写（≤ 5 个字母）不得单独用于匹配；同一条记录（同一个试验 / 同一篇文献）里必须同时出现全称（或长同义词）或基因名才算命中。** 不靠调字母数。
- **修法**：
  1. 病名分两类：全称 / 长同义词照旧；大写短缩写（≤ 5 字母，可含数字）标为 `abbrev`，**不单独检索**（不作为 CT.gov `query.cond`、PubMed 检索词），**不单独作为相关依据**。
  2. 相关性判定：只靠缩写命中的记录，要在同一记录的标题 / Conditions / Keywords / 摘要里再找到全称、长同义词或基因名，找到才算相关；理由里写明两处证据。
  3. 病名路径也加癌症 / 标志物语境排除（与基因路径共用 `genecontext.CANCER`）。
  4. 同一规则用于 3b、3c、L3、3e 所有用病名检索或匹配的地方（逐处排查并在契约里列出）。
- **审批**：B。
- **测试**：正向——"LS-SCLC"、"3BNC117-LS"、"Lumbar Spinal Stenosis (LSS)" 不再使 Leigh 综合征病人命中；反向——"Leigh Syndrome"、"Leigh syndrome (LS)" 仍命中；记录里只写 "CF" 但标题有 "Cystic Fibrosis" → 命中；只写 "CMT" 且有 "MPZ" → 命中；罕见病名本身含 "cancer" 一词的单列测试。
- **评测病例影响**：任何病名有短缩写的评测病例（只会减少误收）。

### N2. L3 文献检索覆盖不到文献常用叫法【系统性】
- **现象**：THRA 检索式只有 MONDO / OMIM 名，文献常用 "resistance to thyroid hormone alpha / RTHα"，0 篇。
- **修法**：L3 检索名单加入（a）"<基因>-related disorder / syndrome / deficiency"；（b）Orphanet 与 OMIM 的同义词（已下载的数据集，不在线临时抓）；短缩写按 N1 不单独入检索式。
- **审批**：A。
- **测试**：THRA 的检索式含 "THRA-related" 与 Orphanet 名；短缩写不进检索式；FOXF1、PSMD12 检索式只增不减。
- **评测病例影响**：没有 GeneReviews 专章的评测病例（支持治疗只能靠 L3 / L4）。

### N3. 换说法的同一行动跨章节重复
- **现象**：SNRNP200 禁忌节 "UV-blocking sunglasses" 与支持治疗节 "UV-A and UV-B blocking sunglasses"。
- **修法**：账本层跨章节查重：同一来源同一句（或同一药物键 / 策略键）在两节各出一条时，按章节优先规则保留一节，另一节记"已在某节"，交叉引用交 Step 4；判不准的列为"可能重复"进审阅，不自动删。
- **审批**：A。
- **测试**：`SAME-SNRNP200-UV-SUNGLASSES` 改为计分；反向——同一句里两个不同措施（"助听器、人工耳蜗"）不合并。

### N4. 多个诊断分支时同一药物键在同一节生成多条
- **现象**：SFTPC 甲泼尼龙（`drug:rxcui:6902`、同一篇 PMID 33179299）两个分支各一条。
- **修法**：3c（及 3a、3b 同类路径）按行动键合并，`applies_to`、`status_by_branch` 记两个分支。
- **审批**：A。
- **测试**：两分支、同一药、同一文献 → 一条行动、两个分支状态；反向——不同药物键不合并。

## 二、语义核查

### 合并评估：S1–S7 能否合并成一个带完整上下文的核查步骤

**结论：能合并 S1、S3、S4、S5、S6、S7 和 D2 的"先例病人基因"部分；S2（措辞）不合并，留在代码。**

它们的共同根因是同一个：**核查（或抽取）只看到孤立的一句话，看不到这句话的上下文与病人信息**，于是按字面做了过宽或过窄的读法——
| 条目 | 看不到的上下文 | 读错的方向 |
| --- | --- | --- |
| S1 GEMIN5 辅酶 Q10 | 摘要另一句写的病人基因 | 过窄：阳性被压成"未报告" |
| S3 丙戊酸 | 句子处在"应避免"小节 | 过宽：豁免读成触发条件 |
| S4 伏立康唑 | 病人因其他适应证用药 | 过宽：不良反应读成治疗先例 |
| S5 避免强光 | "in animal models … rhodopsin" | 过宽：他物种 / 他基因证据读成已确立 |
| S6 FOXF1 肺移植 | "milder form" 的人群限定 | 过窄：有条件建议被整条丢弃 |
| S7 碳酸氢钠 | 病人事实是"乳酸升高" | 过宽："明显酸中毒"被放大成已满足 |
| D2 西地那非 / PXT3003 / 艾地苯醌 | 先例病人的基因 / 亚型 | 过宽：他基因 / 他亚型 / 未说明的先例套到本病人 |

各加一条规则会变成补丁堆（每个新句式再加一条），而且规则之间没有统一的输入。**合并后的步骤**：

- **名字**：上下文核查（context check），每个待写入的条目一次，替代现在分散在 3a / 3c / L3 里的单句核查。
- **输入**（由代码组装，不让 LLM 自己找）：
  1. 完整来源上下文：GeneReviews 是条目所在小节标题 + 所在段落或表格行（带表头）；文献是题目 + 完整摘要（有开放全文时加相关小节）；试验是完整的该条标准及其所属的亚组标题。
  2. 病人信息：基因型、诊断、已识别表型、病人事实。
  3. 拟写入的读法，拆成固定的核查项（每项是一句可判真假的话，都由代码按模板生成）：
     - **对象**："这条证据说的是 <本病 / 本基因> 的人"（S1、S5、D2）
     - **证据类型**："证据来自人"（S5）
     - **用途**："该药 / 措施是为治疗本病或其表现而用"（S4）
     - **方向**："用后 <指标> 改善 / 未改善"（S1）
     - **条件**："这条建议只在 <条件> 时适用"，条件按原文程度，不放大不缩小（S6、S7）
     - **极性**："原文要求避免 X；<例外> 是避免的豁免"（S3，仅禁忌语境）
     - **病人满足条件**："病人的 <事实> 满足 <条件>"（S7；严格按原文程度）
- **判定**（2026-11-11 定）：**每次调用一次性回答全部核查项（结构化 JSON，每项一个判定和一句理由），判 3 次**，即每个条目 3 次调用；逐项全票才算支持（沿用 `support_check` 的合并规则——它本来就是一次调用判所有项）。只问适用于该条目的项（极性只在禁忌节问，用途 / 方向只在老药新用问）。**状态由代码根据各项结果决定**（例：对象不支持 → 先例注明"来自 <他基因> / 基因未说明"并降为有条件；用途不支持 → 移出老药新用、转注意事项候选；极性支持 → 禁忌按一般规则判、豁免另列）。LLM 不直接给状态。
- **测试集**：现有 7 条论断案例（`CLAIM-*`）和 1 条同一行动案例（`SAME-*`）即为它的回归集，按核查项归类；本轮新增写错（核黄素、生酮乳剂、毛果芸香碱、甲泼尼龙、西地那非、PXT3003、碳酸氢钠）补成案例。每条至少一正一反。
- **代价与风险**：见第七节估算（每个条目 3 次调用，平均每例约 \$0.08）。风险是一次问多项时 LLM 漏答——缺答按"不支持"计（现有规则），并统计各项的缺答率。
- **不合并的**：S2 措辞（代码模板）；N 类名称匹配（确定性代码）；D1 诊断规则（MONDO 上下位，确定性）；D2 的试验基因型标准（代码对照病人基因型，确定性）。

### S1. 疗效方向核查看不到"病人是谁"（并入上下文核查）
- **现象**：GEMIN5 辅酶 Q10（另：LRPPRC 核黄素、静脉生酮乳剂，MPZ 毛果芸香碱，SFTPC 甲泼尼龙——原文都报告了改善或缓解）。
- **审批**：B（"未报告"可能变"报告了改善"）。
- **测试**：`CLAIM-GEMIN5-COQ10`（期望支持）；新增核黄素等 4 条；反向——身份句指向别的病时不支持。

### S2. "证据不足"档措辞过强；论断病句【与 S1 同批做】
- **修法**：固定措辞改为中性："The available reports are not enough to judge whether it works."；指标名自带方向词时不再套 "improved"。
- **审批**：A。
- **测试**：任何结论都不含 "no evidence that it is effective"；"neurological improvements" 生成的论断无重复方向词。

### S3. 禁忌语境下例外从句极性（并入上下文核查的"极性"项）
- 丙戊酸。**审批**：B（有条件 → 适用）。**测试**：`CLAIM-RRM2B-VALPROATE-INVERTED` / `-CORRECT`；反向——支持治疗语境 "only if X" 仍是触发条件；禁忌语境 "if X" 仍是触发条件。

### S4. 不良反应报告不是治疗先例（并入"用途"项）
- **规则（2026-11-11 定）**：不良反应报告可转为**注意事项候选**；只有单个病例时写"注意：有个案报告用后加重"，注明是个案，**不写成禁忌**。
- **审批**：B（移除老药新用条目）。
- **测试**：`CLAIM-MPZ-VORICONAZOLE-ADVERSE`；转出的注意事项措辞含"个案"；反向——治疗性报告（GEMIN5 辅酶 Q10、艾地苯醌）仍为先例。

### S5. 他物种 / 他基因的证据不升为已确立（并入"对象""证据类型"项）
- 避免强光。**审批**：A（适用 → 有条件）。**测试**：`CLAIM-SNRNP200-BRIGHT-LIGHT`；反向——"戒烟"（"recommended for all"）仍适用。

### S6. 有人群限定的建议保留限定（并入"条件"项）
- FOXF1 肺移植（"milder form"）。**审批**：A（新增条目为有条件）。**测试**：以有条件写入；反向——无限定的普通建议不变。

### S7. 条件程度不可放大（新增，并入"条件""病人满足条件"项）
- **现象**：LRPPRC 碳酸氢钠 / 枸橼酸钠，原文 "for significant acidosis"，病人事实是"血乳酸升高"，被判为"适用"。
- **审批**：A（适用 → 有条件）。
- **测试**：乳酸升高不满足"明显酸中毒"→ 有条件；反向——病人事实写"严重代谢性酸中毒"→ 满足。

## 三、诊断规则

### D1. 原文点名的病种群压过 ClinVar 指向的更具体疾病【已批准】
- **规则**：原文点名的病种群在 MONDO 中包含 ClinVar 指向的更具体疾病时，取更具体的；无上下位关系时以原文为准。
- **修法**：Step 2 选主诊断时对 "explicit" 候选做 MONDO 祖先检查（已下载的 MONDO 本体）；理由同时记原文名字与 ClinVar 记录。
- **测试**：正向——"Leigh syndrome" + ClinVar LSFC → LSFC；"Charcot-Marie-Tooth disease" + ClinVar CMT1B → CMT1B；反向——无上下位关系 → 原文；原文更具体 → 原文；ClinVar 无记录 → 原文。
- **验收**：Step 2 验收；`acceptance_eval_cases.py --eval` 确认 4 个评测病例诊断不变；盲测 12 例缓存重跑，预期只有 LRPPRC、MPZ 变回更具体的病。

### D2. 亚型 / 基因型限定未对照病人【本轮做（2026-11-11 定：已致 4 条写错，且影响 40002）】
- **现象**：MPZ 病人进了 CMT4J 专用试验和要求 "duplication of the PMP22 gene" 的试验；PXT3003 先例均为 CMT1A；西地那非先例为 MT-ATP6；艾地苯醌先例病人基因未说明（待判）；多病种试验 Acti-Adult 把只针对重症肌无力亚组的 "should be seropositive" 当成本病人的要求（待判）。
- **修法**：
  1. **3b 基因型类标准由代码判**：标准里明确写出基因 / 变异 / 亚型要求时，对照病人已知基因型（确定事实）：要求的基因与病人不同 → 不满足；只要求"基因确诊"不指定基因 → 不判不满足。
  2. **3b 亚组标准**：标准挂在某个亚组标题下（"Myasthenic patients should …"）且该亚组不是本病人的病 → 该条对本病人不适用，不计入未知项。
  3. **3c 先例病人的基因 / 亚型**（并入上下文核查"对象"项）：与本病人不同 → 结论注明"先例来自 <基因 / 亚型> 病人"、状态降为有条件；原文未说明 → 注明"先例病人基因未说明"。
  4. 亚型专用的试验（标题或 Conditions 只写某个亚型）在亚型与病人诊断不符时排除（D1 修好后大部分自然消失，这条作为兜底）。
- **审批**：B。
