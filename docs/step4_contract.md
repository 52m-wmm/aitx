# Step 4 契约：报告组装（v1.0 定稿，2026-11-15）

> 状态：**v1.0 定稿**（2026-11-15，用户答复 10 个待定问题，见第 13 节）。`docs/step4_contract_todo.md` 的全部事项已纳入（各条注明出处），另加用户 2026-11-15 指定的七项。

## 0. 目标与边界

- **输入**：每个病例 Step 1 / 2 / 3 的输出（`out/step1|2|3/<病例>.json`），以账本为唯一内容来源。
- **输出**：每个病例一份 markdown，合成 `[{id, report_markdown}]` 上传文件；另存逐病例的 `out/step4/<病例>.md` 与组装记录 `out/step4/<病例>.json`（每段文字来自账本哪条记录）。
- **Step 4 只呈现，不判断**：不改任何条目的状态、不新增条目、不重新解读来源。状态、条件、证据都以账本为准；Step 4 只做筛选、分组、排序、措辞和核验。
- 报告由系统生成，**不能人工编辑**（比赛硬规则）。

## 1. 总原则

1. **写错比不写更糟**：拿不准的条目宁可留在账本、不写进报告；报告里注明"另有 N 条见账本"（第 7 节）。
2. **每条论断有可验证来源**：引用必须能解析到具体记录（PMID、NBK、NCT、SPL set id、URL），附**来源最后更新日期**（第 8 节）。
3. **缺信息时写条件语句**：条件来自账本的未知要求行，按缺失信息归组（第 5 节），不写"可能适合"之类无依据的软化词。
4. **同一行动不跨章节重复**：账本的 `possible_duplicates` 与跨节交叉引用字段决定只写一处，另一处写"见某节"。
5. **措辞模板化**：结论句来自账本字段和固定模板（3a / 3c 已有结论模板）；LLM 是否参与润色见待定问题 Q1。

## 2. 报告结构

按官方模板顺序，每节都写（空节写检索无结果，第 10 节）：

1. Summary
2. Tier 1：Existing Targeted Therapies / Supportive Management / Contraindications & Precautions
3. Tier 2：Clinical Trial Eligibility / Off-label or Expanded-Access Therapies
4. Tier 3：Bespoke Therapies / Drug Repurposing / Outcome Measures & Ranking

**证据层级**（已确立 / 新兴 / 假设性）：Tier 1 = 已确立，Tier 2 = 新兴，Tier 3 = 假设性；每份报告三层都要写（项目用词约定）。

## 3. 哪些条目不写进报告（留在账本）

| 类别 | 账本标记 | 出处 |
| --- | --- | --- |
| 不适用的条目 | `status_by_branch.*.status == "not_applicable"` | 通则 |
| 年龄段不适用 | `context_check == "limit"` 行、note 含 "age band" | todo 2026-11-12 |
| 孕期专属（非孕期病人） | `pregnancy_notes` / 孕期行不满足 | todo 2026-11-09 |
| 原文不是推荐（描述用法 / 报告无效） | `context_check == "recommendation"` 不满足行，`recommendation_reason` | todo 2026-11-12（R15） |
| 超出每节上限 | 第 7 节 | todo 2026-11-11 |

例外：**禁忌与注意**节的"不适用"不等于"可以用"，写法见第 6.3 节（待定问题 Q2）。

## 4. Summary

固定四块：

1. **诊断**：Step 2 主诊断、状态（确定 / 待定）与备选；待定时写明"以下各节按 N 个可能诊断分别列出"。
2. **最关键缺失信息**：从账本 `missing_information` 取"影响条目数最多"的前 3 项（`why_it_matters` 已有计数），每项写"影响哪些条目、补上后会变成什么"。
3. **用药前需核实**：第 9 节用药安全核对的结果（相互作用、说明书禁忌、外部禁忌清单），只列需要医生动作的。
4. **各节要点**：每节一句，写最强的 1–2 条与状态。

## 5. 条件的写法：按缺失信息归组

- 账本已把未知要求按变量类型合并（3a 的"按变量合并缺失信息"）。报告里同一缺失变量下的条目写在一起："**若 eGFR ≥ 30**：nedosiran 适用；……"。
- 一个条目依赖多个变量时，挂在影响最大的变量下，其余变量列在条目后。
- "可能存在"的表型（Step 2 `possible`）写成"若确认存在 X"。

## 6. 各节规则

### 6.1 Existing Targeted Therapies
- **交叉说明**（todo 2026-11-09、2026-11-12）：本节为空、而支持治疗节里有针对该分支分子机制的药时，写一句交叉说明（KCNT1 / 奎尼丁；PFN1 / 利鲁唑、依达拉奉），判断依据用 3d 已取到的疾病机制与该药的方向记录，不靠 LLM 常识；不重复列出该药。
- 同类多药都适用时写成可选方案（见 6.2）。

### 6.2 Supportive Management
- **同类多药写成可选方案**（todo 2026-11-09，DDC）：择一或按序试用，不排成"全部使用"的清单；分组依据见待定问题 Q3。
- **状态类标签写成具体动作**（todo 2026-11-11，RRM2B "catabolism"）：动作在前、条件在后。
- **指向外部清单的条目**（todo 2026-11-11，CMT 协会清单）：写成"用药前对照 <清单名> 核对"，附清单出处。
- **孕期句只进孕期段落**（todo 2026-11-09）。
- **L3 无结果 / L4 兜底**（todo 2026-11-05）：写明"已检索文献（检索式、日期、篇数），未发现明确的管理推荐"，并指向 Tier 2 相关条目；落到 L4 时节首写 "No disease-specific management recommendations were found; the following is symptomatic management."；不能把"没找到推荐"写成"不需要管理"。

### 6.3 Contraindications & Precautions
- 只写对本病人成立或条件成立的条目；条件写法同第 5 节。
- 外部清单条目同 6.2。

### 6.4 Clinical Trial Eligibility
- 有条件的试验**按未知项数从少到多排序**（todo 2026-11-04），其次按试验类型与阶段。
- 只收其他基因的试验（基因型规则判不满足）不写。
- 每分支逐条分析上限 10 条（3b），超出的写"另有 N 条相关试验未逐条分析，见账本 / ClinicalTrials.gov 检索式"。

### 6.5 Off-label or Expanded-Access Therapies
- 带药物层面疗效方向（阳性 / 阴性 / 结果不一致 / 部分改善 / 未报告）与逐篇先例（设计、病例数、方向）（todo 2026-11-05）。
- 只有阴性报告的药物的位置、是否同时在禁忌节提示：待定问题 Q4。
- 结果不一致时并列写出阴性与阳性原文。
- 膳食补充剂类加"非 FDA 批准药品，产品质量和剂量缺乏监管"。
- 同一药物同时在 3b 和 3c 时互相注明"见对方章节"。

### 6.6 Bespoke Therapies / Drug Repurposing / Outcome Measures & Ranking
- 3d 提供四个字段：`classification`、`premises_complete`、`human_precedent`、`approved_or_in_trial`（todo 2026-11-05）；3e 提供候选药与"对本亚基选择性未知"类标注。
- **Outcome Measures & Ranking** 由 Step 4 统一排序 3c / 3d / 3e，规则不放进任何子节点（todo 2026-11-05）；排序规则见待定问题 Q5。

## 7. 每节条目上限（todo 2026-11-11，架构原则 4）

- 每节写进报告的条目设上限，3b、3c 各取证据最强的前 3–5 条，其余留在账本，报告注明"另有 N 条见账本"。
- 排序依据各节已有字段（3b：未知项数、试验类型、阶段；3c：疗效方向与证据规模；3d：四个字段）。
- 具体上限值见待定问题 Q6。

## 8. 来源更新日期（todo 2026-11-11，Argus II）

- 每条引用写来源最后更新日期：GeneReviews 章节 "Last Update"、说明书版本日期、试验登记最后更新、PubMed 出版日期、指南版本。
- 器械 / 产品类条目尤其要写；来源早于一定年限时提示"可能已过时，请核实是否仍在供应"（年限见待定问题 Q7）。

## 9. 用药安全核对（2026-11-15 新增）

对报告里状态为适用或有条件的**所有药物**（3a / 3c / 3e，含支持治疗里的药）：

1. **两两相互作用**：每对药查相互作用，结果写进 Summary "用药前需核实"与对应条目。数据源见待定问题 Q8。
2. **说明书禁忌**：每个有 FDA 说明书的药，取说明书 Contraindications / Warnings 小节，对照病人事实（年龄、性别、肾肝功能、已知诊断、在用药物）；成立或未知都写，未知写成条件。
3. 外部禁忌清单（6.2）在这里统一列出。
4. 核对只呈现来源原文与对照结果，**不给剂量建议、不替医生做取舍**。

## 10. 检索无结果的写法（2026-11-15 新增）

- 账本的负面证据（`negative` 条目）写成："已检索 <数据库>（检索式 <…>，<日期>，返回 <N> 条，按 <规则> 排除 <M> 条），未发现 <本节对象>。"
- 区分"检索了、没有"与"无法评估"（3d 的 `unable_to_assess` 写明缺的是哪个前提）。
- 不写"无需治疗""无已知疗法"这类超出检索范围的结论。

## 11. 格式校验与引用核验

- 结构校验：章节齐全且顺序正确；每节非空（或为检索无结果写法）。
- 引用核验：每个引用的 id 能解析到记录（离线校验格式，联网验收解析 HTTP 200）；引文逐字出现在账本的已核实证据里。
- 去重校验：同一行动键在报告中只完整出现一次。
- 不写进报告的条目（第 3 节）一条都不出现。

## 12. 测试与验收（按项目规矩）

- 离线测试：每条规则正反用例（例如：非推荐条目不出现；同类多药写成可选方案；超上限写"另有 N 条"；孕期句不进一般段落）。
- 验收：练习病例逐份检查结构与引用；用 `docs/clinical_reading_rules.md` 审查清单逐条过；先单例试跑。
- 不涉及新的 LLM 调用时不需要报价；若 Q1 决定用 LLM 润色，按花钱规矩先报价。

## 13. 已定决策（原待定问题，用户 2026-11-15 答复）

1. **Q1 措辞**：事实部分（药名、状态、条件、数字、引文）全部由代码按模板从账本填；LLM 只润色 Summary 和节间衔接句，不得新增事实，每句可追溯到账本 ID，Step 5 逐句核验；用 LLM 时先报价。**第一版不用 LLM**，Summary 也由模板生成。
2. **Q2 禁忌节的不适用条目**：不逐条写，节末写"另有 N 条对本病人不适用，见账本"。
3. **Q3 同类多药分组**：按来源原文的并列关系分组（同一表格行 / 同一句），不引入新的药物分类数据源。
4. **Q4 只有阴性报告的药物**：报告无效 → Off-label 节末写"已有报告无效，不推荐"；病情加重 / 不良反应 → 禁忌与注意；两者都有时写在禁忌节，Off-label 节交叉引用。
5. **Q5 Outcome Measures & Ranking**：固定顺序，不用权重——证据强度（人体先例阳性 > 可报名试验 > 分子层面可行 > 仅有机制）→ 病人匹配（未知项少优先）→ 获取途径；每条附一句可读的排序理由。
6. **Q6 每节上限**：3b 5 条、3c 5 条、3e 3 条、支持治疗按症状分组约 10 条；已有靶向和禁忌不设上限；超出写"另有 N 条，见账本"。
7. **Q7 过时提示**：来源早于 5 年提示可能过时，器械 / 产品类 3 年；GeneReviews 显示其更新日期。
8. **Q8 相互作用数据源**：FDA 说明书的 Drug Interactions 与 Contraindications 两节（openFDA），沿用逐字引文核验；暂不用 DDInter（许可不明）。
9. **Q9 多个待定诊断**：合并写，共用条目写一次并标"Applies to: A, B"，只适用于一个诊断的单独标注。
10. **Q10 语言**：报告正文英文；查看页面中文。
